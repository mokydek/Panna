# Тест-план

## Честный статус

Многопользовательские тесты Roblox Studio нельзя считать пройденными только по чтению исходного кода или успешной сборке Rojo. Текущий узкий Studio CLI smoke подтвердил структуру, загрузку модулей, `BallMath`, мир, арены и `RemoteRegistry`, но не выполнял Heartbeat-зависимые игровые действия. Отдельный исторический Local Server room-smoke с четырьмя клиентами подтвердил вход в две комнаты до текущей переработки мяча; это не текущий расширенный ball-test. Две попытки текущего расширенного прогона в Studio `0.732.0.7321040` были заблокированы до загрузки игровых scripts внешней ошибкой provisional rating для локального `universe 0` с кодом 500. Точные границы зафиксированы в [фактических проверках](TESTING.md); документ ниже задаёт воспроизводимую процедуру для оставшегося покрытия.

Фиксируйте для каждого прогона дату, commit SHA, версию Studio, число клиентов, платформу, результат и ссылку на журнал/видео дефекта.

## Уровни проверки

1. **Структура:** `scripts/validate-project.ps1`, затем `rojo build`.
2. **Статика:** `stylua --check src` и `selene src`, если инструменты установлены.
3. **Play Solo:** загрузка сервера, мира и одного клиента без необработанных ошибок.
4. **Local Server:** минимум два клиента, полный цикл 1v1.
5. **Опубликованный тестовый Experience:** DataStore, реальные устройства и сетевые условия.

Ни один уровень не заменяет следующий.

## Подготовка

- используйте отдельный тестовый Experience;
- синхронизируйте текущий commit через Rojo;
- очистите Output перед тестом;
- для DataStore заранее решите, какие тестовые профили допустимо менять;
- не включайте API Services у production Experience;
- запускайте минимум два клиента; для полной проверки параллельности шести комнат потребуется 12 клиентов, а тринадцатый проверяет ожидание при полной загрузке.

| M-11 | Выход во время очереди | Отключить ожидающего игрока | Запись удаляется, другой игрок не блокируется |

| M-13 | Граница таймера | Создать гол/панну сразу после точного `EndsAt`, до следующего timer poll | Событие не меняет завершившийся период |

| A-02 | Все комнаты заняты | Добавить тринадцатого/четырнадцатого клиента в общую очередь | Игроки остаются в очереди до освобождения комнаты |

| B-01 | Падение мяча | Сбросить мяч ниже разрешённого Y | Сервер возвращает мяч в корректную точку |
| B-02 | Слишком высокая скорость | Создать аномальную скорость в тестовой среде | Сервер ограничивает/восстанавливает состояние без гола |

| P-04 | Защитник перехватил | После пересечения отдать владение защитнику, повернуть его и позже вернуть мяч атакующему | Кандидат отменён при чужом owner/last touch; панна не засчитывается |

| P-06 | Реакция после прохода | После корректного пересечения защитник отходит, затем атакующий вовремя возвращает владение без чужого касания | Обычное движение защитника не отменяет уже подтверждённый проход; панна засчитывается один раз |
| D-01 | Первичная загрузка | Новый игрок входит в тестовый Experience | Создаётся профиль со значениями по умолчанию, `DataLoaded` корректен |
| D-02 | Повторный вход | Изменить статистику легальным матчем и переподключиться | Подтверждённые данные восстанавливаются |
| D-03 | Ошибка DataStore | Имитировать недоступность в безопасной тестовой среде | Нет crash и перезаписи живого профиля пустыми данными |
| D-04 | Идемпотентность | Попытаться завершить один матч несколькими событиями | Награда и статистика применены один раз |
| D-05 | Session lock | Имитировать живой lock другого session ID и затем истёкший lock | Живой lock не перезаписывается и даёт безопасный fallback; истёкший можно атомарно приобрести |
| D-06 | Конкурентные save | Совместить autosave, выход и shutdown в тестовой обвязке | Per-player guard сериализует записи, чистое завершение освобождает lock в пределах budget |
| D-07 | Stale save после takeover | Дать lease A истечь, загрузить/освободить профиль с B, затем позволить A сохранить старую копию | A получает отказ даже при уже пустом lock; stale-данные не записываются без exact ownership |
| D-08 | Disconnect при load/save | Отключиться сразу после захвата lease и отдельно во время занятого autosave | Завершившийся load или сериализованный final save освобождает lock контролируемо |
| D-09 | Fallback и рейтинг | В published test войти с `DataSessionFallback = true` и запросить очередь/завершить матч; повторить в Studio | Published ranked блокируется; Studio разрешает матч только для разработки, но `RewardMatch` не применяет несохраняемый прогресс |
| D-10 | Быстрый rejoin того же сервера | Перезайти тем же UserId до завершения позднего release старого `Player` | Каждый load имеет новый lease ID; старый объект не сохраняет данные и не снимает lock новой сессии |
| D-11 | Потеря подтверждённого save | После успешной загрузки имитировать transport/ownership failure autosave, затем восстановить запись | Сессия становится `DataSessionFallback`, ranked/награды блокируются; только успешный exact-owner save снимает unsafe-состояние |
| D-12 | Shutdown во время load/save | Начать медленный load и save, затем вызвать shutdown | Новые load не стартуют; активные loading/saving ожидаются в пределах общего budget, поздний lock не остаётся без попытки release |
| D-13 | Выход fallback-игрока | Отключить игрока после неуспешной загрузки без приобретённого lease | Очистка завершается без tight loop/заморозки серверного потока |

## Ввод и интерфейс

Проверьте отдельно:

- клавиатуру и мышь;
- геймпад с корректными подсказками текущего устройства;
- телефон в портретной и альбомной ориентации;
- планшет;
- разрешение с safe-area/notch;
- смену устройства ввода во время матча;
- отсутствие перекрытия счёта, таймера и мобильных кнопок;
- читаемость countdown, гола, панны, победы и поражения;
- восстановление HUD после второго матча без дубликатов.

## Adversarial-проверки

Проводите только в собственном тестовом Experience.

| ID | Запрос | Ожидаемая реакция сервера |
| --- | --- | --- |
| X-01 | Неизвестное имя действия | Отклонить без изменения состояния |
| X-02 | Строка вместо Vector3/таблицы | Отклонить без исключения обработчика |
| X-03 | NaN, infinity, нулевое/огромное направление | Отклонить или безопасно нормализовать по контракту |
| X-04 | Сотни Remote в секунду | Ограничить; сервер и честные игроки продолжают работать |
| X-05 | Удар из лобби или чужой арены | Отклонить |
| X-06 | Действие дальше допустимого радиуса мяча | Отклонить |
| X-07 | Клиентская попытка назначить счёт/монеты | У клиента нет такого доверенного пути |
| X-08 | QueueRequest во время матча | Отклонить без разрушения текущего матча |
| X-09 | Client-owned персонаж мгновенно телепортируется к мячу внутри bounds и отправляет действие | Серверная история выявляет невозможный скачок, откатывает позицию и отклоняет действие; повторные нарушения возвращают на spawn |
| X-10 | Третий игрок входит в занятую арену и пытается столкнуться с мячом | Spectator collision group не взаимодействует с мячом, scan возвращает игрока к `StreetSpawn` |
| X-11 | В тестовой обвязке имитировать ошибку регистрации collision groups | Сервер пишет предупреждение и продолжает периодический eject без crash |

## Производительность и длительный прогон

1. Запустите последовательность минимум из 20 коротких матчей.
2. Сравните число активных Instances и соединений в начале и конце.
3. Проверьте MicroProfiler на лишнюю работу каждый кадр.
4. На слабом мобильном устройстве пройдите всю улицу и проверьте все шесть комнат при `StreamingEnabled`.
5. Убедитесь, что временные эффекты и старые мячи удаляются.
6. Проверьте сервер с максимальным целевым числом игроков.

Зафиксируйте фактические FPS, server frame time и потребление памяти; не используйте непроверенные цифры в описании игры.

## Критерии приёмки первого MVP

Версию можно пометить как проверенный MVP, только если два игрока не менее трёх раз подряд могут:

1. загрузиться в одном лобби;
2. выбрать комнату через `EntryPrompt` (и отдельно проверить общую очередь);
3. дождаться соперника и получить выбранную арену;
4. использовать заявленные футбольные действия;
5. забить серверно подтверждённый гол;
6. завершить основное или дополнительное время;
7. увидеть одинаковый результат;
8. получить награду ровно один раз;
9. вернуться к уличной точке комнаты;
10. переподключиться и восстановить сохранённую статистику.

Отдельно должны пройти R-01…R-07, X-01…X-11, D-05…D-13, изоляция шести параллельных комнат и ненаграждаемые disconnect-сценарии. Любой разрыв с ожидаемым результатом является `NO-GO` для рейтингового публичного запуска, пока не исправлен и не превращён в regression test.
